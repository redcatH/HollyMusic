# 平台插件 v1 设计

[平台插件开发指南](platform-plugins.md)提供可直接导入的最小示例、字段契约和测试步骤。

一个 JavaScript 脚本包可以注册一个或多个平台。管理员导入后即可使用已启用的功能，也可以在后台按平台测试。汽水音乐 `qs` 是首个接入平台，单曲搜索和发现内容由平台插件提供，播放由已启用的 LX 音源提供。QQ、网易云、酷狗、酷我和咪咕的内置实现随后接入同一接口。

## 使用离线 demo

升级后按现有部署流程应用 SQLite 迁移。用管理员账号打开「系统管理 → 平台插件」，点击「导入脚本」并选择[离线 demo 插件](../examples/platform-plugins/demo-catalog.js)。导入成功后即可使用已启用的搜索和发现功能。仓库不包含真实平台适配脚本。

用 demo 验证导入、搜索、歌单详情、榜单和漫游。接入真实平台时，在「音源管理」启用对应平台，再用「测试歌曲」搜索并选一首歌。目录插件只负责元数据，具体播放可用性以取流测试为准。

## 产品操作

### 管理员

导入 `.js` 文件时，后台校验脚本声明并启用该包可用的平台功能。页面显示包名称、版本、各平台的功能、当前提供方和请求域名。若某项功能由其他插件包提供，导入会保留现有提供方，管理员可勾选相关功能并确认切换。

导入同一插件包的新版本会切换其功能绑定，并停用该包在新版中移除的功能。管理员可以手动停用单项功能，也可从变更记录回滚一次导入、更新或切换。删除插件会移除该包的全部版本，也可仅删除所选版本。删除会解除这些版本的功能绑定，保留变更记录。恢复已删除的版本需要重新导入脚本。

「功能测试（可选）」默认收起，展开后可按需测试。测试歌单、榜单或电台列表成功后，对应的详情测试会自动填入返回的第一条 ID。搜索测试使用自选关键词。

平台详情独立显示播放状态。可播放时展示匹配的已启用音源。只有浏览能力时，显示「可浏览 · 暂无可用播放音源」，并提供到音源管理的入口。汽水播放测试选用由搜索或发现返回的真实歌曲，通过现有音源测试执行。目录功能测试使用元数据请求。

### 听歌用户

搜索页根据启用的单曲搜索能力显示平台，并加入「全部」。发现页按可用能力显示推荐、分类、歌单搜索、榜单或漫游，使用现有布局、卡片和空态。只提供搜索歌单能力的平台显示搜索入口，支持详情后才展示可进入的歌单详情链接。某项请求失败时，对应区域保留已加载内容并提供重试，其他平台继续显示结果。

收藏、歌单、历史和分享使用稳定的歌曲 ID。停用或更新目录插件后，已有歌曲使用库中保存的信息展示，匹配的播放音源仍可按歌曲 ID 取流。停用发现详情后，原收藏的公开歌单条目仍可见，打开时提示该平台的歌单详情暂不可用。

```mermaid
flowchart LR
  Upload[管理员上传多平台脚本] --> Registry[平台与功能注册表]
  Registry --> Worker[独立插件执行进程]
  Worker --> Metadata[统一元数据和分页]
  Metadata --> Library[歌曲入库与目录缓存]
  Library --> Views[搜索、发现与 Subsonic]
  Views --> Playback[现有播放与下载路由]
  Playback --> LX[按平台匹配已启用的 LX 音源]
```

## 脚本接口

脚本是单个 UTF-8 `.js` 文件，以一次 `holly.register(package)` 注册。包包含 `apiVersion`、稳定的包 `id`、名称、版本，以及 `platforms` 数组。每个平台可以引用同一个处理函数，通过宿主传入的平台和参数复用实现。平台 ID 使用小写字母和数字，首字符为字母，最多 16 位。汽水统一使用 `qs`。

```js
holly.register({
  apiVersion: 1,
  id: 'example-catalog',
  name: '我的平台脚本',
  version: '1.0.0',
  platforms: [
    {
      id: 'qs',
      name: '汽水音乐',
      origins: ['https://api.example.com'],
      handlers: { searchSongs, searchPlaylists, listPlaylists, getPlaylist },
    },
    {
      id: 'tx',
      name: 'QQ 音乐',
      origins: ['https://example.org'],
      handlers: { searchSongs },
    },
  ],
})
```

示例中的处理函数由脚本作者实现。只有注册了处理函数的能力才会显示在候选中。宿主传给处理函数 `input` 和 `context`，其中 `context.platform` 由宿主填入，`context.request` 提供限时 JSON 请求。请求域名按本次调用的平台检查，共用处理函数也受该平台的授权范围约束。注册阶段执行声明和本地逻辑，网络访问随具体能力调用开始。

| 能力 | 参数 | 返回值 |
| --- | --- | --- |
| `searchSongs` | `keyword`, `cursor`, `limit` | 歌曲分页 |
| `searchPlaylists` | `keyword`, `cursor`, `limit` | 歌单分页 |
| `listPlaylistCategories` | 无 | 分类及各自的稳定 ID |
| `listPlaylists` | `categoryId?`, `cursor`, `limit` | 推荐或分类歌单分页 |
| `getPlaylist` | `id`, `cursor`, `limit` | 歌单信息和歌曲分页 |
| `listCharts` / `getChart` | 列表无参数 / `id`, `cursor`, `limit` | 榜单目录 / 榜单信息和歌曲分页 |
| `listRadioStations` / `getRadioTracks` | 列表无参数 / `id`, `cursor`, `limit` | 电台或场景列表 / 歌曲分页 |

- 分页结果包含 `items`、`hasMore`、可选 `nextCursor` 和可选 `total`。只有上游返回可信总数时才设置 `total`。游标缺失、重复或失效时结束分页或提示重新加载。没有稳定分页的推荐流提供「换一批」。每次刷新按单次响应展示并去重。
- 歌曲返回字符串 `id`、歌名、歌手和可选的专辑、封面、`durationMs`、音质。宿主校验长度和类型，限制返回条数及响应大小，并生成 `source` 和 `uid`。汽水各入口统一映射到播放音源接受的歌曲 ID。上游只提供视频 ID 或缺少可验证的歌曲 ID 时，该条结果仅作展示。汽水各接口的时长分别做单位转换。
- 公共歌单、榜单的 ID 采用各平台稳定标识。主程序按平台和资源类型存储路由及引用。插件自定义分类和漫游 ID 以其提供方为作用域，避免切换脚本后误用旧参数。
- 同一包重复声明平台、包 ID 冲突、未知接口版本、无有效处理函数或返回契约不符时，后台显示具体校验错误。一个平台的功能可以来自多个包。每个平台的每项功能只路由给一个已启用提供方，冲突时展示当前提供方和候选，管理员确认切换。分类与按分类取歌单由同一提供方处理。

## 版本与运行

脚本内容、摘要、解析出的平台声明和测试记录随现有 SQLite 数据备份。版本内容不可变，同一包的不同版本可供回滚。

| 记录 | 身份和用途 |
| --- | --- |
| 插件包 | 稳定的包 ID。平台列表随版本变动。 |
| 插件版本 | 包 ID、版本号与内容摘要。保存原脚本及解析后的声明。同一版本号对应同一份内容。 |
| 启用记录 | 平台 ID 与能力联合唯一，指向具体包版本和当前启用状态。 |
| 测试记录 | 包版本、平台、能力和测试样本，保存结果、耗时及测试时间。 |
| 变更记录 | 保存操作人、时间和受影响能力的前后版本，用于审计和批量回滚。 |

导入在同一个 SQLite 事务中保存脚本版本、更新功能绑定和写入变更记录。手动启用时校验版本是否声明对应功能。重复导入同一已启用脚本时复用版本，绑定无变化时也复用当前状态。并发修改返回冲突。

每次调用绑定平台、能力和脚本版本。运行器按需加载该版本，运行中的请求维持原版本直到结束。进程异常或达到时限时，由宿主取消网络请求并回收执行进程，后续请求重新加载已启用版本。插件失效后可以从后台停用或回滚，旧版本请求的结果继续写入旧版本缓存。

执行进程复用仓库现有的子进程、受控网络请求和限额机制，并按平台声明校验目标域名及每次重定向。第三方代码只接触注册、结构化入参和托管请求接口。进程环境通过白名单构建，文件、子进程、直接网络和主应用凭据由宿主及部署权限隔离。权限机制无法启用时，后台将插件标为「运行环境不支持」。日志记录平台、能力、版本、耗时和错误类型，排除认证字段与上游响应正文。

## 缓存与兼容

| 数据 | 处理方式 |
| --- | --- |
| 平台能力 | `/api/platforms` 返回平台名称和已启用的功能。搜索、发现和管理界面使用同一注册表。启用后通知当前界面重新获取。 |
| 搜索和发现 | 复用 `searchCache` 和进行中请求去重。按平台、能力、提供方版本、规范化参数及分页状态索引。合法空结果与上游错误分别处理，失败不会被当成空结果缓存。推荐使用较短 TTL，搜索和详情先沿用仓库可配的缓存策略。 |
| 游标 | 上游游标、提供方和脚本版本关联。网页请求只携带宿主返回的续页标识，过期或版本变更时从第一页重新加载。内置平台保留原页码接口，搜索和发现逐步接入游标响应。 |
| 歌曲信息 | 复用 `db.ts` 的事务和 checksum 入库。以平台和歌曲 ID 精确匹配。单曲搜索缺少音质时按未知展示，并保留歌单或榜单已取得的同歌音质字段。插件版本不进入歌曲 ID。 |
| 音频与离线 | 继续按实际播放档位使用现有取流、下载和缓存管线。目录缓存失效与音频缓存使用各自的生命周期。 |

网页的 `/api/search` 和 `/api/discover/*` 通过注册表调用能力，保留现有调用入口及五个平台的排序、收藏与标识兼容。发现列表增加可选的游标响应供插件平台使用。移动端复用相同能力清单及交互。管理员通过 `/api/admin/platform-plugins` 导入并启用脚本、查看绑定、测试功能、调整绑定或回滚。

Subsonic `search3` 调用同一注册表，并保留各平台支持的搜索前缀。对游标平台分批读取到所需 `songOffset` 和 `songCount`，设置单次请求页数、结果数和总体时限。超出预算时返回已取得并落入请求范围的结果，同时记录原因。搜索结果及聚合缓存包含启用的提供方版本。`getSong`、收藏和歌单读取继续用稳定歌曲 ID。音质字段为空的已入库汽水歌曲仍按现有客户端偏好进入真实取流验证，返回的音频规格以已验证文件为准。

## 汽水首版与验收

1. 用包含 `qs` 和另一平台的示例包验收导入即启用、按需测试、单项停用和一次导入的回滚，重启后验证绑定恢复。
2. 接入汽水单曲搜索、歌单搜索、推荐与分类、歌单详情和榜单。漫游作为独立能力加入发现页。使用此前验证的公开元数据请求编写新的插件适配，按各入口的真实响应转换歌曲 ID、音质和时长。
3. 在音源管理、测试平台和平台标识中支持目标平台。真实平台插件由部署者自行维护，管理员启用后验证真实取流。未取得单曲音质时显示未知，首播后展示实际命中的档位。
4. 验证同一首歌从搜索、歌单、榜单或漫游入库时使用同一 ID。网页播放、下载、收藏、历史、分享与 Subsonic 使用同一记录。至少验证两页搜索、一个歌单、一个榜单及一次从已保存记录的播放，覆盖真实 ID 与音质回退。
5. 验证一个包里的某项能力失败时，同包其他能力继续可用。验证提供方冲突、导入预检报错、并发更新、回滚、版本切换中的翻页，以及禁用目录能力后的收藏读取。覆盖桌面和移动端的入口、加载、重试与仅浏览状态。
6. 测试通过后逐个平台将现有五个平台的实现挂到同一接口。在与既有结果、收藏和播放行为对齐后，再把对应功能交给可更新的脚本包。

仓库中的离线 demo 已覆盖公开的插件契约、分页、歌单详情、榜单和漫游流程。真实平台的元数据请求、取流和不同来源之间的歌曲 ID 对齐属于部署环境的接入验收。
