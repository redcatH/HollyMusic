**Subsonic 与网页音质选择统一：实施 TODO**

日期：2026-10-15。状态：T1–T5 核心代码与本地自动化验证已完成，准备 PR/CI 与 preview 发布；真实 amcfy 客户端实测待有客户端环境时执行。第七部分为独立后续任务。

目标：复用网页现有的音质选择规则，修复 Subsonic 的码率映射，让原格式请求从歌曲支持的最高档位开始，并让歌曲信息展示对应的资源品质。

**一、已确认的行为**

- [x] 两端继续共用 `MusicSourceManager.getMusicUrl()` 和 `audioServe`。
- [x] 指定档位存在时直接使用；不存在时优先选择不高于指定档位的最高可用档。
- [x] 如果所有可用档位都高于指定档位，选择其中最低档，保留“可播放优先”的向上兜底。
- [x] 原格式／不限码率从 `flac24bit` 开始，按 `flac24bit → flac → 320k → 128k` 选择。
- [x] 网页继续保留浏览器解码能力限制，以及当前歌曲解码失败后的降档重试。
- [x] 选择档位与音源解析是两步：歌曲声明支持某档，不保证上游此刻一定能取得该档。
- [x] 不增加“仅无损”模式。本次允许解析失败后降级，不保证每首歌都能返回 FLAC。

兼容约定：`maxBitRate` 在标准协议中表示码率上限；本项目保留向上兜底后，它在资源不匹配时表现为选择偏好，可能超过该上限。低于 128kbps 的请求也只能尝试现有最低档 128k。应在 API 文档中明确这项行为，不声称提供严格限码率或实时转码。

**二、当前问题与修改位置**

| 问题 | 当前实现 | 计划处理 |
|---|---|---|
| 客户端指定 320kbps，内部却变成 128k | `lib/subsonic-stream.ts` 的码率区间映射 | 修正参数到起始档位的映射 |
| 原格式／不限码率仍默认 320k | 同上，未读取 `format`，默认目标为 320k | 原格式从最高档开始 |
| 目标缺失时 Subsonic 直接从最高档找 | `lib/subsonic-media.ts` 的 `selectQuality()` | 复用 `lib/quality-options.ts` 的 `resolveQuality()` |
| 搜索、详情等优先标注 320k | `resolveSubsonicMediaMeta()` | 按歌曲声明的最高支持档位生成资源信息 |
| 旧搜索结果继续携带 MP3 元数据 | `lib/cache-key.ts` 与客户端缓存 | 更新搜索缓存版本，联调时刷新客户端数据 |
| 请求档位与后端实际降级档位未分开返回 | `lib/music-source-manager.ts`、`lib/audio-serve.ts` | 单独跟踪共享缓存与实际音质问题，见第七部分 |

**三、参数映射方案**

这些规则只负责生成起始偏好；最终档位由共用 `resolveQuality()` 和歌曲支持列表决定。

| 条件，按优先级匹配 | 起始偏好 | 说明 |
|---|---|---|
| `format=raw` | `flac24bit` | 原格式优先；即使同时携带码率参数也从最高档开始 |
| 非 raw，合法正整数 `maxBitRate >= 320` | `320k` | 320、500、800 等都按现有有损档位处理；不能把某个数字当作 FLAC 固定码率 |
| 非 raw，合法正整数 `0 < maxBitRate < 320` | `128k` | 192、256 等选择 128k；低于 128 的请求采用可播放优先兜底 |
| 码率不限，`format=mp3` | `320k` | 格式作为偏好；歌曲只有更高档时仍沿用已确认的向上兜底 |
| 码率缺省、空值或 0，且没有 MP3 偏好 | `flac24bit` | 默认最高支持档位；`format=flac` 也从最高 FLAC 档位开始 |

- [x] 以小型纯函数实现参数归一化，放在 `lib/subsonic-stream.ts` 或独立的 Subsonic 参数模块；公共音质工具不依赖 `NextRequest`。
- [x] `format` 去首尾空白并转小写。除上述已识别格式外，沿用码率／默认选择，并明确不实现其他编码格式的转码。
- [x] `maxBitRate` 去首尾空白；负数、非数字、带单位文本、小数、超出安全整数范围视为无效参数，通过现有 `subsonicError()` 返回参数错误。避免 `parseInt('320abc')` 被默认为合法请求。
- [x] 明确 `format=raw` 的优先级：它直接进入原格式分支，不依赖同时传来的码率字段。
- [x] 记录请求格式、码率、归一化偏好和选中档位；使用 `logger`，不记录含鉴权参数的完整 URL。
