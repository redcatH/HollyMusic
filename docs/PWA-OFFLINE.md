# PWA 离线启动与本地歌曲缓存

当前实现将应用资源和歌曲分开保存。应用更新只清理旧应用资源，不清理本地歌曲；音频 `/api/audio` 可由 SW 复用下载和缓存，其余 API 与 Subsonic 请求仍走网络。

## 使用流程

1. 通过 HTTPS 或 localhost 打开生产版本，登录一次。
2. 在「本地歌曲」页面确认「离线启动资源已就绪」。
3. 联网播放时，支持当前协议的 SW 会复用播放请求下载完整音频；播放约 3 秒后，页面开始将完整响应保存为本地歌曲。没有可用 SW 时才独立请求完整音频。保存成功后，歌曲出现在「本地歌曲」中；开始播放或浏览器已经缓冲一部分不代表缓存完成。
4. 断网后重新打开应用，会自动跳转到 `/offline` 本地歌曲页面，保留原有侧栏、手机顶部导航和播放器，首页、推荐、搜索、收藏、歌单、历史等在线页面入口置灰禁用；可点选本地歌曲、切歌、暂停和拖动进度。已有播放队列和进度仍按账号恢复；队列中未缓存的歌曲会停止并提示。
5. 恢复网络后自动校验会话，也可以点击「重新连接」。会话有效时恢复在线功能，过期时进入登录流程。同账号校验成功后，当前仍在播放的网络音频会按原有约 3 秒延迟重新触发完整缓存，不重新加载播放音频；已取消但尚未结束的旧下载不会阻止新任务排队，同一代任务仍去重。

首次访问且尚未缓存资源时不能离线启动。开发环境会注册 `/sw.js?mode=development`，用于验证音频下载复用，但不预缓存应用壳、不拦截页面或热更新资源。验证离线启动需要先运行 `pnpm -C frontend build`，再使用 HTTPS/localhost 的生产静态服务或 `pnpm -C frontend exec vite preview`。

## 应用壳

`frontend/package.json` 的构建脚本在 Vite 构建完成后运行 `scripts/build-service-worker.mjs`：

- 收集构建产物中的 JS、CSS 等所有 `/assets/` 文件，以及首页、主题初始化脚本、manifest、应用图标。
- 先编译页面与 SW 共用的播放协议，再以资源内容和完整 SW 代码计算版本，将独立构建配置注入 `frontend/dist/sw.js`，不解析或替换 Worker 源码中的变量声明。修改共享协议也会更新版本。必需资源缺失或产物语法错误会使构建失败；生产 Worker 缺少有效配置时拒绝启动。
- 安装时完整预缓存；任何必需文件失败，都不激活该版本。登录、设置页面也能注册 SW。
- 页面导航优先请求网络，4 秒超时或网络失败时回退缓存首页，支持深层路由和 `?source=pwa`。
- 清单中的公开静态资源直接使用对应版本缓存，动态 API、音频及跨域请求不进入应用壳缓存。
- 更新版本等待旧页面全部关闭再激活，避免自动接管正在播放的页面。激活时只清理 Holly 旧应用壳缓存，保留 `holly-audio-v1:*`。

部署须保持 `/sw.js`、`/manifest.json` 可重新校验，保留 nginx 的 SPA fallback。所有构建须经过 `pnpm -C frontend build`，不能仅调用 `vite build` 后发布，否则缺少产物级预缓存清单。旧版本升级后需联网打开应用，再关闭旧页面并重开，使新 SW 生效。

## 页面与 SW 的播放协议

`lib/playback-protocol.ts` 是通信契约的唯一来源，定义消息名与字段、协议版本、缓存名与键、分块清单及边界校验。页面直接导入，`scripts/service-worker-source.mjs` 使用已有 TypeScript 编译器将其编译进 classic SW；生产构建和 Vite 开发服务共用这个入口。该模块只允许类型导入，保持无运行时依赖，不访问页面或 SW 的全局状态。

页面仍负责播放器状态、缓存调度和握手超时，SW 仍负责下载、Range 响应、内存与写盘预算。这些逻辑可独立演进；只要双方交换的消息及缓存格式不变，就无需调整协议。

当前协议为 v1。握手携带 `protocolVersion`，没有版本字段的旧消息按原有 v1 兼容，页面继续接受旧 SW 的 Blob 响应。显式不兼容版本会拒绝共享下载，页面回退到独立缓存请求，不影响在线播放；拒绝握手不会释放原有播放。以后如需不兼容修改，应升级协议版本并定义回退行为；修改持久化清单或缓存格式还需分别调整格式版本与缓存命名，不能只改一端。

## 本地歌曲

`lib/offline-audio.ts` 直接使用浏览器 Cache Storage，不新增依赖，也不缓存播放 URL：

| 项目 | 实现 |
| --- | --- |
| 隔离 | 按账号建缓存，歌曲 UID + 请求音质作为键 |
| 触发 | 音频就绪且播放约 3 秒后，串行保存 SW 共享的完整响应；无可用 SW 时独立请求 `/api/audio` |
| 完整性 | 页面保存的完整响应须为 200，Content-Length 合法且实际字节数一致；SW 可将覆盖整首的合法 206 重组为完整响应。拒绝局部音频、错误 JSON、截断或超过当前总容量的响应 |
| 提交 | 完整下载后将音频与歌曲元数据一起写入一条缓存记录，成功后才展示 |
| 播放 | 读取完整音频生成 Blob URL；原生 audio 支持本地 seek，切歌、卸载时释放 URL |
| 音质 | 在线播放优先读取当前账号同渠道、同歌曲、同音质的浏览器缓存，未命中或读取失败才请求服务端（服务端继续优先磁盘缓存）；离线播放优先匹配当前音质，没有时选择设备可解码的已有缓存档位。从本地列表建立的队列会为每条歌曲保存本地来源和缓存音质，切歌、插播及恢复会话均沿用；缓存缺失时提示，不转为在线播放 |
| 容量 | 每账号默认总容量 500 MB，可在「本地歌曲 → 设置」调整，最低 100 MB；无数量或单首固定上限，同曲不同音质分别统计空间 |
| 清理 | 按最近使用时间淘汰；调低容量若需清理，先展示数量和释放空间，经确认后保存；页面支持单个删除、清空全部；清理或切换账号会取消当前页面未完成任务 |
| 失败 | 网络、超时、配额和存储失败不阻断在线播放；未缓存成功的歌曲不显示为可离线播放。正在播放的网络音频发生网络错误时，优先用当前账号同渠道、同歌曲、同音质的完整本地缓存恢复当前进度；未命中再执行原有错误处理，暂停时不自动出声 |

容量设置保存在当前浏览器的当前账号下，其他标签页会同步读取。MB 按 1,000,000 字节、GB 按 1,000,000,000 字节计算。单首歌曲若超过总容量上限，则跳过缓存，保留已有歌曲且不影响在线播放；提交前会重新读取容量设置。

有可用 SW 时，播放与本地缓存复用同一次完整下载，正常路径不为缓存额外下载一遍；完整下载可能比用户实际听到的片段更多。无 SW、旧 SW 握手超时等回退情况下，后台完整请求仍会增加服务端到浏览器的传输量；临时分块读取失败时，播放所需区间也可能回退网络。新音频先写入成功，再按容量淘汰旧歌曲；如果浏览器没有临时写入空间，则放弃本次缓存并保留旧歌曲。写入期间取消会移除新条目；淘汰已经开始后则保留新条目并完成清理，变更后即使清理出错也会通知列表刷新。缓存不保证永久保存，浏览器可能因空间不足或用户清理网站数据而移除。多标签页在支持 Web Locks 的浏览器中串行提交和淘汰；不支持时采用当前页面内串行处理。

快速下载暂时领先浏览器写盘时，SW 会在 2 MB 写入队列上限处等待空间，最长等待 250 毫秒；写盘腾出空间就继续缓存。持续积压时放弃本次缓存，保留正常播放，并记录 `[SW] write-queue` 警告。

排查缓存失败时，可查看页面控制台的 `[SW]`、`[offline]` 和 `[playback]` 日志：包含读写或清理阶段、错误名称和原因。SW 同一阶段的诊断每 30 秒最多一次；页面对同一次播放捕获的读取错误只记录一次。正常缓存未命中和主动取消不告警。

## 离线身份和边界

成功联网校验后，只记住本机最近账号名称，用于选择本地歌曲缓存。连接失败时进入独立离线模式，`authenticated` 不会变成 `true`，保留原有应用外框，将在线页面入口置灰禁用；直接访问其他路由也会跳转到本地歌曲。明确收到未登录、401/403、强制改密时不保留离线入口；主动登出成功后也移除入口。

这是浏览器本地数据隔离，不是加密存储。缓存保留在当前浏览器配置中，登出不会自动删除音频文件；可以在登出前通过「本地歌曲」清空。离线播放不补报历史，不包含离线搜索、歌单编辑、歌词/封面下载或后台同步；页面被系统挂起后，也不保证后台下载持续执行。

## 验证

自动测试覆盖完整/部分/截断音频、账号隔离、重复下载、取消写入、缓存淘汰、离线身份回退、会话过期、本地播放恢复及 SW 路由回退与缓存清理，也覆盖真实页面代码与编译后 SW 的消息通信、旧协议兼容、不兼容版本回退、分块清单校验及协议变更后的构建版本更新。

真机验收：联网等待资源与歌曲缓存完成 → 关闭所有页面 → 断网重开 PWA → 点选缓存歌曲并拖动进度 → 切换歌曲 → 恢复网络校验登录 → 发布新版本后确认歌曲仍保留。iOS 主屏 PWA 的后台挂起、浏览器存储回收和音频格式兼容仍需真机验证。
