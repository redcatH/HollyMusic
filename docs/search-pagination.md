# 搜索分页与完整榜单（#128）

## 产品规则

- Web「全部平台」只获取各平台首批结果，明确提示切换平台查看更多；失败渠道可单独重试。
- 指定平台提供「加载更多」，失败保留已有结果并重试原页；请求中的重复操作合并，切换搜索后丢弃旧响应。
- 同平台按歌曲 UID 去重，保留上游顺序，不合并跨平台/不同版本的歌曲。不根据展示数量推断上游页数。
- 榜单按上游声明的总数分页取全，校验数量、重复页和期数；QQ 详情每批最多 50 首。完整获取并入库后才发布缓存。

## 数据契约

沿用 `/api/search` 的 `page/limit` 及原返回字段，增加 `hasMore/nextPage`。服务端规范化有效页大小（网易最多 20），响应 `limit` 为有效大小。下一次请求使用响应的 `nextPage/limit`，禁止前端按歌曲数计算偏移量。

平台适配保留原始条目数，网易使用上游 `hasMore`，酷狗/咪咕依据展开前的分页单位判断。错误响应与空结果分开；上游宣称未结束却返回空页时不缓存成功结果。

搜索服务负责请求合并、版本化缓存、批量入库及 UID；API 路由负责认证与严格参数验证。前端只维护当前搜索会话，不另建长期缓存。切换平台可命中服务端同条件的首批缓存；离开再返回保留当前会话。

## 缓存及资源边界

- 搜索页缓存键包含契约版本、平台、关键词、页码及有效页大小，沿用可配置搜索 TTL。
- 榜单缓存升级版本，TTL 10 分钟，同榜单并发请求合并。缺页、期数变化、详情缺失或入库失败均不写成功缓存。
- 现有 `searchCache` 按键前缀设置独立 LRU 容量预算（条目数与估算序列化字节）；网页深度搜索不会淘汰 Subsonic 分区。单条超限不缓存。
- 分页请求设数量上限及整体时间预算，达到保护边界报错，不宣称完整。缓存仍为进程内；重启清空。

默认容量预算：Web 搜索 1000 条/16 MiB，Subsonic 搜索 1000 条/16 MiB，发现页 200 条/32 MiB，其余搜索缓存 1000 条/16 MiB。分别使用 `WEB_SEARCH_CACHE`、`SUBSONIC_SEARCH_CACHE`、`DISCOVERY_CACHE`、`OTHER_SEARCH_CACHE` 前缀加 `_MAX_ENTRIES` 或 `_MAX_BYTES` 覆盖；字节预算是序列化估算值，不是 Node 堆内存的硬上限。搜索 TTL 统一使用 `SEARCH_CACHE_TTL_MS`（默认 210 分钟）。

当前交互使用明确的「加载更多」按钮，避免滚动或空白区域自动连续发起请求。首批请求与追加请求均支持取消；取消一个浏览器请求不会终止其他用户共享的服务端请求。

## 兼容范围

保留歌曲 UID、db.ts checksum、API 的旧字段、LX 搜索调用方式及 Subsonic XML/JSON 协议。Web 聚合预览限制只作用于页面，不能下沉为平台搜索限制。

Subsonic 当前每平台仅请求首批再按 offset 截取，其深度分页限制是独立问题。本次验证共享适配层（特别是 limit=10）的兼容性，不引入 Subsonic 结果快照或更改聚合排序。AI 建歌单、推荐任务继续使用原搜索签名。

## 验收

1. 单平台加载、结束、失败重试、重复请求、搜索切换竞态及 UID 去重。
2. 聚合模式无分页入口，成功源可先展示，失败源可重试。
3. 网易连续分页无偏移遗漏；分组展开不影响酷狗/咪咕分页。
4. QQ 300、酷我 300、酷狗 500 首模拟完整榜单及真实上游核验；缺页、重复页、期数变化、详情批次缺失不得缓存。
5. 缓存命中/合并/过期/分区淘汰；Subsonic 既有协议回归、前后端类型检查与构建。
