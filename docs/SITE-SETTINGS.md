# 站点设置

管理员从侧栏账号菜单进入「系统管理 → 站点设置」，可以修改实例范围的站点名称和简介。未配置的实例默认使用 `Holly Music` 和「把时间交给音乐」，无需额外迁移或初始化数据。

- 名称必填，去除首尾空白后最多 100 个字符；简介最多 200 个字符，可留空。两者均为单行纯文本，不支持 HTML。
- 表单预览只展示草稿。「保存设置」成功后才写入数据库并更新当前页面；其他用户刷新页面后读取新设置。
- 「恢复默认值」只恢复表单，仍需保存才能生效。保存失败保留草稿与原有站点设置，可重试。
- 第一版沿用现有图标，不提供上传 Logo 或修改 favicon。
- 登录页和分享页保留 `Powered by Holly Music`；用户菜单的「关于 Holly Music」提供项目源码、问题反馈与 MIT 许可信息。

## 展示与离线行为

导航、登录/首次设置、连接提示与手机首页显示站点名称。首页浏览器标题为站点名称，其他页面为「页面名称 · 站点名称」。分享页同时更新品牌与 Open Graph 站点名称，并转义动态文本。

浏览器缓存最近一次成功读取的公开设置，用于离线重开；存储禁用、缓存损坏或首次访问时回退默认值。读取失败不会阻塞登录、音频播放或离线歌曲。管理员保存后，先前发出的旧读取响应不能覆盖新值。离线期间无法修改设置。

`/manifest.json` 在 nginx 和 Vite 开发服务中代理至动态 API `/api/site/manifest`，保持原有启动地址、scope、图标及应用身份。名称和简介随站点设置变化；默认短名称仍为 `Holly`，自定义时使用站点名称。已安装应用的更新时机由浏览器及操作系统决定，部分系统需要重新安装。Service Worker 对清单优先联网，4 秒失败或超时后回退最近成功的清单；其他静态资源沿用现有缓存策略。

自定义反代需保留这条清单代理，不能仅分发构建目录中的默认 `manifest.json`。`vite preview` 会继承本项目的代理配置，完整验证时需同时启动 3000 端口的 Next.js 后端。

## 接口与持久化

- `GET /api/site/settings`：匿名读取，仅返回 `name`、`description`，不公开管理配置。
- `GET /api/admin/site-settings`、`PUT /api/admin/site-settings`：仅管理员。PUT 使用 JSON `{ "name": "Holly Music", "description": "把时间交给音乐" }`，包含同源检查和输入校验。
- `GET /api/site/manifest`：匿名读取 PWA 清单；失败返回 503，避免以成功响应覆盖离线清单。

设置使用现有 `SystemSetting` 表中的 `site.name`、`site.description`，服务端在同一事务内读取与写入两个字段。不新增数据表或迁移；数据随现有 SQLite 持久化与备份。已有实例只保存 `site.name` 时，保留原名称并为简介补默认值。
