# 音源测试与导入

音源管理提供「测试歌曲」「最近测试」及每行的测试按钮。先为需要验证的平台各选一首歌曲，再上传脚本或添加订阅。脚本通过隔离初始化后形成候选；快速测试、完整检查和试听均在同一窗口完成。勾选需要启用的平台后确认导入，也可以仅保存为停用音源。

订阅更新先拉取候选内容，当前音源继续使用；确认更新时使用已测试的同一份脚本。测试期间修改过原配置或脚本时，提交返回冲突，需重新准备候选。已开始的测试及上传、订阅候选关闭窗口后可以从「最近测试」恢复查看。

已有音源点击测试按钮时仅预校验脚本，不保存草稿或占用候选配额；点击「开始测试」或「完整检查」后才保存测试记录。未开始就关闭窗口不会留下空记录。开始时会重新核对脚本摘要，内容已变更时需重新打开窗口。

「最近测试」中的测试记录只包含已启动的任务，旧版本留下的空测试草稿也不会显示。未测试的上传、订阅及订阅更新候选显示在「待处理音源」中，并标记「未测试」，可继续处理。

## 启动与执行方式

音源测试随应用一起运行，沿用项目现有 Node.js 24 环境。完成数据库升级后，按原有方式启动应用即可使用；没有额外服务、监听端口、令牌或执行模式需要配置。原有容器部署同样由应用直接创建 Node 子进程。

```sh
pnpm dev
```

生产环境使用原来的构建、启动或容器升级流程。应用打包会包含测试子进程入口、LX 兼容引擎及音频解析依赖。

每次初始化、指定歌曲取链和音频分析使用独立的一次性 Node 子进程。音源脚本在现有 LX VM 中执行，测试进程与正式播放的常驻音源进程分开。正式播放器的 inline 设置不改变测试的子进程执行方式。

测试沿用播放运行器的环境变量白名单及 Node 权限参数，支持时限制文件访问，并设置 384MB V8 老生代堆上限。主进程不会将认证密钥、数据库地址、Node 启动注入参数或放开内网访问的播放设置传给测试进程。V8 堆上限并非整个进程的操作系统内存配额；VM 与子进程也不等同于操作系统级沙箱。

LX 网络请求由父进程受控转发，校验 DNS 的全部地址，将已验证地址固定到连接，并对每次重定向重新校验。每次执行最多 30 个脚本请求、4 个并发网络请求；聚合脚本超过并发上限的请求会排队。单个响应最多 2MB，网络传输与进程输出均有大小上限。

本地同时最多执行两个测试操作。初始化及取链每次最多 25 秒，音频解析最多 30 秒；结束、超时或取消后终止子进程，同时取消网络请求，进程关闭后才释放执行名额。

## 数据与升级

按项目现有流程生成 Prisma Client、应用迁移后重启应用：

```sh
pnpm prisma:generate
pnpm exec prisma migrate deploy
```

新增表 `SourceTestDraft` 保存候选脚本、归属、歌曲快照和最近报告。测试歌曲使用类型校验后的 `SystemSetting`。原音源配置兼容；确认提交时增加 `importId` 用于幂等检查。上传和订阅 API 现在返回候选，不会直接启用；API 调用者需迁移至 `/api/admin/source-tests/:id` 的 `run` 与 `commit` 操作。

更新保留原脚本路径。替换前写入 `config/.source-import-journal.json` 恢复记录，配置提交后删除；启动音源管理器前先恢复未提交的替换。不要手动删除正在使用的恢复记录。

候选可操作 24 小时，报告保留 30 天。临时音频位于 `.cache/source-tests`，创建候选时清理过期文件。该目录需可写，禁止由静态 Web 服务器直接暴露；试听 API 检查管理员身份和任务归属，并支持 Range。当前调度面向项目现有的单个持久 Node 实例，多实例部署需要共享任务调度器后再启用该功能。

## 检测含义

- 快速测试每项最多读取 1MB；完整检查每项最多读取 64MB，每轮总下载预算 256MB，任务最长 15 分钟；临时音频空间上限 1GB，启动任务时预留预算，空间不足时可删除旧报告释放。
- 未设置歌曲的平台跳过。默认测试脚本与歌曲共同声明的音质，不换源、不降级、不使用正式播放音频缓存。
- 时长读取失败是「无法判断」；完整检查触及大小限制是「未完成」。仅识别音频不等于浏览器可播放，试听由浏览器另行验证。
- FLAC 编码及位深确认不是原生无损认证，单首 VIP 歌曲通过不代表整个曲库可用。
- 完整下载不代表每一帧已完整解码，试听错误也可能来自当前浏览器的编码支持。
- 测试报告不会自动改变平台配置，用户始终通过确认按钮应用选择。
